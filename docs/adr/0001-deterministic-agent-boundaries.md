# Keep business outcomes deterministic around the language model

The Media Hub Agent uses the language model to understand goals, extract fuzzy clues, resolve references, and choose read-only capabilities, while backend state machines own tool obligations, current-work context, pending requests, download confirmation, idempotency, revalidation, and verified outcomes. A factual request cannot finish as pure conversation: the model gets one internal correction opportunity, then the backend deterministically executes the required capability. Any reply based on a business tool is rendered by a versioned deterministic template; only general conversation remains free-form. Model memory may propose a media-title hypothesis, but it cannot become current work until TMDB verifies it. This prevents repeated confirmations, invented success claims, context loss, terminology drift, and inconsistent result layouts without giving up flexible natural-language planning.
